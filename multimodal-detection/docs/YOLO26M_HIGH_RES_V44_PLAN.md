# 基于 V4.4 的 YOLO26m 与高分辨率提分方案

日期：2026-10-02
状态：**实施与验证方案；尚未训练 YOLO26m，也没有证据表明它已超过 V4.4。**

## 2. 目标结构与可复用代码

目标是**真正的 YOLO26m-P2 三模态模型**：保留 V4.4 的 RGB、IR、Depth 独立特征提取，可靠深度掩码、共用/私有证据、跨尺度记忆和残差融合；将编码器/检测主干及检测头迁至 YOLO26m，并保留 P2/P3/P4/P5 四尺度检测。模型仍输出一套融合后的检测结果。

仓库固定的 `multimodal-detection/vendor/ultralytics` 为 `8.4.138`，已有 [`yolo26-p2.yaml`](../vendor/ultralytics/cfg/models/26/yolo26-p2.yaml)、端到端检测头、相关损失和 MuSGD 代码。官方也提供 [YOLO26m 权重与说明](https://docs.ultralytics.com/models/yolo26)；**官方没有 `yolo26m-p2.pt` 权重**。应从公开 `yolo26m.pt` 初始化形状匹配的 backbone/neck/检测层，列出成功迁移、未匹配和新初始化参数；P2 新增部分不能假称已有预训练。YOLO11s 的 V4.4 权重不能直接当作 YOLO26m 初始权重。

当前 V4.4 代码需要实质性适配，至少包括：

1. [`mm_yolo/independent_model.py`](../mm_yolo/independent_model.py) 的 `SpatialDetect` 直接读写旧 `Detect.cv2/cv3/reg_max` 和 P2 头。以 YOLO26 的四尺度双头输出建立新模块，确认融合特征分别进入定位与分类分支；保留训练所需的一对多/一对一输出。
2. [`mm_yolo/train.py`](../mm_yolo/train.py) 目前显式创建 `v8DetectionLoss`，辅助分支也依赖旧输出契约。迁移后应使用与 YOLO26 原生头一致的目标分配、框回归和渐进损失，并记录所用优化器。仅更换骨干、保留旧头/旧损失只能称为“26 骨干混合模型”，不能拿它代表完整 YOLO26。
3. [`mm_yolo/eval.py`](../mm_yolo/eval.py) 与 [`mm_yolo/submit.py`](../mm_yolo/submit.py) 当前按旧 DFL 输出解码与 NMS。新版本分别测试官方默认一对多+NMS路径和可选的一对一推理路径，主比较先固定与 V4.4 相近的 NMS 口径；逐图检查坐标、类别、空预测和 `max_det=100`。
4. [`mm_yolo/model.py`](../mm_yolo/model.py) 的 `resolve_infer_canvas()` 会把与 checkpoint 不同的 `--imgsz` 改回训练画布。增设**显式**推理画布覆盖开关，并把实际画布写入日志/预测元数据；默认行为仍用 checkpoint 记录值。否则任何“提高推理分辨率”的 A/B 都可能实际跑在 736×1280。

迁移验收：新模型在仅开 RGB、辅助残差零初始化时，其输出与相同 YOLO26m-P2 RGB 主路数值一致；P2/P3/P4/P5 形状正确；三模态梯度能到达对应分支；保存/重载预测一致；训练、验证和提交三条路径使用同一预处理与类别映射。**跨架构不要求与 V4.4 输出逐位相同。**

## 3. 分辨率策略

先把“整图推理变大”和“高分辨率重新训练”作为两个不同实验。三模态必须同步做几何变换；保持原图宽高比，并对最终框进行原图坐标还原。建议的画布均是 32 的倍数：

| 画布 | 相对 736×1280 像素量 | 用途 |
| --- | ---: | --- |
| `736×1280` | 1.00× | V4.4 与 YOLO26m 的模型对照画布。 |
| `864×1536` | 1.41× | 首选高分辨率训练候选；先做推理 A/B 和显存检查。 |
| `1088×1920` | 2.22× | 仅在 864×1536 有明确整体收益、单卡显存与提交耗时允许时试。 |

放大画布不会恢复传感器没有记录的细节，但会减少输入缩小造成的信息损失，使小框占更多特征格；收益、误报与定位变化必须实测。4090 24 GB 上不要预设 YOLO26m 三编码器、P2、864×1536 还能用 batch 4。按 batch 2、再 batch 1 的顺序做 50–100 个真实训练 step 检查；用累积维持接近原有效 batch，同时记录实际吞吐、显存峰值和 BN 行为。训练时启用已有 encoder checkpointing；若 batch 1 仍溢出，停止该尺寸，不通过隐藏缩小模型或砍掉模态来“完成同一实验”。

## 4. 最小实验矩阵与训练预算

固定 `configs/split_s42.json` 的 1600 训练/400 验证、12 类映射、随机种子、标注版本、推理 `conf=0.001`、NMS IoU `0.7`、每图最多 100 框。原 400 张已经被反复用于研发选择，因此小幅波动只能算筛选信号；最终候选尽量加做一个按场景分组的新划分，最终仍以官方新分数确认。

| 编号 | 模型与输入 | 目的 | 训练要求 |
| --- | --- | --- | --- |
| A | 原 1600 张版 V4.4，736×1280 推理 | 锁定可复现基线 | 不新增训练。 |
| B | 同一 V4.4 权重，864×1536 整图推理 | 单独测提高推理画布是否有益 | 不新增训练；先修画布覆盖并核对实际尺寸。 |
| C | YOLO26m-P2 + V4.4 三模态融合，736×1280 | 单独测架构收益 | 从 YOLO26m 公开权重建立同结构任务起点，再走两阶段。 |
| D | 与 C 同结构、同预训练来源，864×1536 | 单独测高分辨率训练收益 | 与 C 同划分、同轮数和尽量接近的有效 batch；只在 C 正常收敛、尺寸可行后跑。 |

V4.4 的 Stage A 需要同结构的任务 checkpoint，且默认先冻结既有 RGB/Neck/Head。因此 C/D **不能**用 V4.4 的 YOLO11s `best.pt` 直接进入两阶段：先在 1600 张上建立 YOLO26m-P2 RGB 任务起点，再克隆/初始化 IR、Depth 支路，最后进入独立辅助预训与联合融合。任务起点本身的训练时间应单独记账。

为节省 4090 时间，先做能跑通的形状/梯度/提交 smoke test，再做计划总轮数固定的短训筛选，例如任务起点收敛后 Stage A `18` 轮、Stage B `24` 轮。短训配方必须从一开始固定学习率终点；若要判最终上限，重新安排独立的 `36+36` 完整实验，或从一开始预设 `36+36` 日程并在第 18/24 轮检查是否提前停止。不要将“短余弦日程的 18+24”直接续成“原版 36+36”并声称两者等价；也不要把短训 C/D 与已经完整训练的 V4.4 直接比较模型能力。

每个候选保存：代码提交、权重来源与迁移报告、训练/验证文件清单哈希、配置、每轮 mAP50–95、mAP50、mAP75、逐类 AP、按短边尺寸分组召回、框误差、误报数、显存、每轮及每图耗时。主要成功条件是 **12 类整体 mAP50–95** 在同口径验证中稳定提高，且大类没有显著退步；球、三轮车和小目标只作解释性指标。对 400 张做按图或按场景的配对重采样，避免凭单次 0.001 左右差异决定全量训练。

## 5. 我认为值得加入的两项低成本改进

### 5.1 先做数据与模态审计

2000 张样本较少，漏标、错类、边界不一致、近重复场景和 RGB/IR/Depth 配对偏差都可能比更大模型更限制泛化。对所有训练图做：文件 stem 与尺寸对应检查、标签越界/异常小框检查、深度有效区比例、IR 黑边与几何偏移统计。再以现有 V4.4 预测对训练图排序，只人工复核最高风险图；可参考 [Cleanlab 目标检测标签审计](https://docs.cleanlab.ai/stable/tutorials/object_detection.html)，但模型和标注冲突不等于标注必错。若用训练集预测排序，尽量使用该图未参与训练时的预测，避免模型记忆掩盖错误。修正只作用于官方允许的训练标签，并记录每一项人工确认。

### 5.2 把“小目标裁剪”改为目标尺度控制，但仅作受控增强

当前 [`target_crop_M()`](../mm_yolo/data.py) 的裁剪宽度下限含 `W * frac`、`frac∈[0.58,0.88]`，小目标自身的 `bw*1.6` 几乎不会生效。因此“提高裁到球的概率”并不能显著放大球。若 C/D 的小目标漏检仍是主损失，再对训练集做**三模态同步、以目标短边决定尺度、保留上下文与完整标签**的裁剪增强，球只是其中一类。先只改变这一项，与同权重、同轮数对照；限制每图重复采样和过大放大，避免把模糊目标放大成伪清晰样本。整图高分辨率训练与该增强的作用可能重叠，须先分别测再考虑组合。

IR 配准/质量插件和切片推理保留为后续条件实验：只有模态消融显示 IR/Depth 明确拖累或错位审计找到系统性问题时，才从远端 V6.1 工具借用诊断；只有新模型整图结果出现可验证的候选漏检时，才重试候选触发切片。不能在第一版同时加进来。

## 6. 交付顺序和退出条件

1. **复现与诊断：**确认 1600 张版 V4.4 权重、标签、400 张评估和真实画布；完成 B 的整图尺寸 A/B 与基础数据审计。
2. **模型迁移：**完成 YOLO26m-P2 RGB 主路、权重匹配报告、三模态残差接入、原生损失及提交解码；CPU/小 batch 与 4090 梯度检查全部通过。
3. **短训筛选：**建立 YOLO26m 同结构任务起点，跑 C；若稳定且整体有希望，再跑 D。实际 GPU 预算由 50–100 步和首个完整 epoch 推算，不把官方 640×640 FLOPs 当作本项目训练耗时。
4. **确认与提交：**胜出候选在独立留出方案或场景分组复验后，预先定好配方，使用官方允许的 2000 张训练图制作最终权重。此时原 400 张已参与训练，不能再称独立验证集。最终只报告官方成绩与 `51.4` 比较，并保留可回退的 V4.4 提交包。

任一关出现 OOM、NaN、旧 V4.4 基线不能复现、检测头/损失不匹配、类别或坐标错误、整体 AP 无持续改善或提交耗时超限，就停下修复或回退。**新架构值得试，不保证比 V4.4 高分；可归因的实验结果比一次性叠加所有想法更重要。**
